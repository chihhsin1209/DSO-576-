# Cleaning rules declared before running the pipeline

Scope: full All_Beauty reviews and full All_Beauty product metadata, following the newer project vision PDF. The older branch's Appliances proposal is retained in docs/project-start.md for provenance only.

Business question: Which All Beauty parent listings should a category manager review first for possible missing or unclear information raised repeatedly in customer reviews? Main future comparison: number of distinct retained review records mentioning a theme per parent listing, with at least two reviews per theme and available metadata. This assignment prepares data; it does not assert that keyword mentions prove information gaps.

| Rule | Reason | Check |
|---|---|---|
| Keep raw downloads unchanged; pin the HF revision and verify SHA-256 and file sizes before parsing. Fail on invalid JSON. | Preserve provenance and catch interrupted downloads. | Input hashes before/after; exact row counts; source manifest. |
| Keep identifiers as strings; trim outer whitespace only; retain leading zeros and case. | ASINs can look numeric. | Type profile and real record 9585. |
| For human prose, normalize NFC, decode HTML entities, replace only br tags with newlines, and strip outer whitespace. Preserve capitalization, punctuation, typos, internal spacing, and other tags. | Make evidence readable without changing meaning or erasing expressions such as <3. | Changed-field counts, before/after cases, independent br-tag and ampersand checks. |
| Empty human text becomes null; retain review rows with missing bodies. Preserve empty lists/dictionaries; clean prose in features/description and string detail values without changing keys or nested image/video data. | Missing prose is not evidence of satisfaction or absence of a theme; empty structures express no supplied content. | Missing table before/after and valid-metric denominators. |
| Parse integer ratings in 1..5, nonnegative integer helpful votes and rating counts, nonnegative finite prices, finite average ratings in 1..5, exact boolean purchase flags, and integer Unix-ms timestamps. Invalid values become null and receive a flag, never zero. | Avoid impossible values and false certainty. | Conversion and domain-error counts by field; data types in SQLite schema. |
| Flag timestamps outside May 1996 through September 2023; keep the source timestamp and UTC date, exclude flagged dates from time metrics. | Documented dataset period; unusual does not always mean wrong. | Timestamp bounds and temporal denominator. |
| Count exact original JSON-object duplicates separately from repeated identifiers. Remove only exact duplicates, retain first source line, and log duplicate-to-survivor mappings. | Avoid double-counting the same evidence while retaining distinct same-user or variant reviews. | Raw = kept + exact duplicates; reconcile rating/helpful totals. |
| Do not assume (user_id, asin, timestamp) is unique. Retain distinct repeated candidates and flag them. For metadata, quarantine every conflicting nonduplicate parent key from the join. | No guaranteed natural review key; ambiguous metadata could multiply rows. | Repeated-key counts and nonunique metadata-key report. |
| Left join retained reviews to unambiguous metadata by parent_asin, many-to-one. Null keys do not match. Keep unmatched review rows and flag them. | Missing listings should not cause silent loss or many-to-many expansion. | Joined rows equal retained reviews; unmatched rows/keys, unused metadata keys. |
| Keep out-of-category-looking listings and missing categories flagged for manual review. Keep all valid prices and helpful-vote outliers. | All_Beauty taxonomy is noisy; extreme values alone are not errors. | Category coverage, maxima, 99th percentile, unmatched counts. |
| Use nonmissing denominators for rating means, negative-review rates (1-2 stars), and purchase rates. Exclude missing parent keys from product metrics and report their count. No sales or revenue inferred. | Prevent denominator mistakes and overclaiming. | SQL metric queries and independent sums/counts. |
| Share 50 genuine cleaned joined records: first cases covering HTML, entity decoding, missing text, leading-zero ID, unmatched metadata, duplicate-key cases and missing listing fields; fill remaining slots by SHA-256 order of record_id. | Difficult cases plus deterministic variety, not a representative sample. | Unique sample IDs, <=50 rows, membership and match checks against full cleaned output. |
